# 截图后的异步 OCR 与文字优先评估

适用于 `preview --json` 和 `action resume --json` 成功返回的 PNG。原图始终保留；`--open-only` 没有截图，不触发 OCR。向下滚轮、阅读停顿保持不变；截图到底后不向上恢复。收集的 `action resume` 成功截图后保留原有关闭前等待，再点击左侧随机安全空白退出；推荐／搜索／深度搜索的 `preview` 截图后保持简历打开并停在底部。两者都必须等本人的 OCR 和 Agent 结果完成，再决定下一步，等待期间不处理下一人。推荐需要从列表联系时，评估完成后才退出简历，再核验目标并沟通。

材料落盘到文字提取及 Agent 结构化结果完成，目标30秒；执行 [AGENTS.md 的简历解析提速五项执行规则](../AGENTS.md#简历解析提速五项执行规则)：文字优先、一次判断、减少重复材料、缩短输出、区分收集与筛选，并按其计时规范记录耗时。该目标不修改 OCR API 的失败处理或强行保证宿主推理时长。

## Agent 执行顺序

OCR 成功后，本地结构化收集可使用[紧凑交接与计时](resume-analysis.md)；Agent 提交字段和证据行号，固定脚本写盘，避免重复生成保存代码。该工具不会重新 OCR 或替代岗位评估。

1. 保存截图回执，核验候选人身份及 `path`，按 [AGENTS.md](../AGENTS.md) 优先选择完整长图并检查已有任务或成功结果，避免对长图及其覆盖的截图、切片重复 OCR。复用结果时核验候选人归属、`status=completed` 及输入一致性（`imageSha256`），不能仅凭文件名复用。截图回执的 `ocr.status=not-started` 表示此次截图未启动 OCR，不代表此前没有同图任务或结果。
2. 对尚未覆盖的必需材料，自动通过已核验安装的公开命令 `node .\dist\cli\index.js ocr '<path绝对路径>' --layout boss-online-resume --json` 启动 OCR。使用宿主的异步 shell/进程工具保存任务 ID，让命令在后台执行；不得只说“稍后识别”而不调用。使用参数数组或正确的 shell 引号，不直接拼接候选人名字。原命令在完成时才退出，CLI 不创建守护进程。
3. OCR 等待期间可整理本人的已有记录；不可提前评分、触达或违反逐人处理 SOP 去操作下一位候选人。等待该进程完成，不重复发起识别，也不重新截图。
4. 每份结果须退出码为 0 且 `status=completed`，并核对 `imagePath` 对应本人的截图。同一候选人有多张截图时，等待所有必需 OCR 结果成功返回并核验归属后，按 [AGENTS.md](../AGENTS.md) 汇总各份 `textPath` 的文字及来源，再按本轮固定规则进行一次完整评估，不逐张反复评分。`imageSha256` 用于审计输入，`boxesPath` 保留原坐标、置信度与分栏归属；原图是核验依据，OCR 文本不是事实补全器。
5. `needsReview=true` 时按 `lowConfidenceIds` 核对截图中的相关区域；数字、专业、学校等决定性字段有疑点时也核对原图。不能把 OCR 漏字当作候选人不具备某项经历。
6. 网络、HTTP、响应格式或版面歧义会返回非零退出码及失败回执路径。保存错误并停止该人的依赖评估；不自动换服务、重试、重截图或用不完整文字评分。用户决定后续处理。已获准的不联系继续模式仍按其规则判断是否可以继续其他人。

## 服务与结果

- 默认接口为 `http://ylorb.top:9002/ocr`，可用 `BOSS_OCR_URL` 显式配置完整 HTTP(S) URL。已验证该端口提供 HTTP；不自动降级 HTTPS、不关闭证书校验。
- 上传 `multipart/form-data`：`image_file`（PNG）、`use_det=true`、`use_cls=true`、`use_rec=true`。此命令只上传指定本地图片，不连接 BOSS 浏览器、不发送消息。该外部 OCR 调用是本流程明确的文件处理步骤，不授权直接请求 BOSS 接口。
- 请求前同时检查原 PNG 字节数与像素高度：仅当不超过 3 × 1024 × 1024 字节且高度不超过1984像素时上传原图；否则一次确定段数，取字节需求 `ceil(原图字节数 / 3145728)` 与高度需求的较大值。高度超过1984时，高度需求为 `ceil(原图高度 / (1984 - 256))`，否则为1。沿高度均分；例如1160×11064长图分为7段，即使文件小于3 MiB也不能跳过高度限制。相邻段通常重叠 256 像素（边界各延伸 128 像素，极矮图片受高度限制），不缩放。全部裁剪编码后预检每段实际大小和含重叠区的高度，任一段超过 3 MiB 或1984像素 则在任何上传前报错，列出段号、字节数和几何位置；不自动增加段数。按从上到下的固定顺序请求，共用一次超时预算，不递归裁剪、不重试。所有段全部成功后恢复原图坐标，每个重叠区在共同无文字间隙选择分界线，只保留各段负责范围内的文字；任一边界无安全间隙则明确失败。
- 分段调用额外保存每段的 `part-N.png` 和 `part-N.raw.json`；此时 `raw.json` 是分段文件索引。`result.json` 的 `split.maxHeightPx` 记录1984像素上限，并记录各段尺寸、纵向偏移、哈希、状态、请求用时和合并分界线数组 `merge.seamYs`、被消重的框 ID；旧字段 `merge.seamY` 仅两段时为该分界线，其余为 null。`boxes.json` 保留原图坐标及每个框的分段来源和局部坐标。原图及全部原始响应归档，低置信度或决定性字段存疑时按需核对原图；合并失败不输出部分文字。
- 默认总请求超时 60000ms，可指定 `--timeout-ms 1000..120000`。仅支持有效 PNG，最多 20 MiB / 8000 万像素；PDF/Word 附件不是这个入口的输入。
- 每次调用在 `<截图绝对路径>.ocr/<唯一ID>/` 保存 `raw.json`、`boxes.json`、`text.txt` 和 `result.json`。原截图不覆盖、不删除；不同调用不覆盖旧结果。`running` 不是完成；进程中断时不可消费半成品。
- 在线简历固定纵向排版，必须显式使用 `--layout boss-online-resume`：按文字框中心纵坐标分行，同行按左到右排序，保留日期、标签和提示，不自动猜栏、不失败后换算法。同行文字框包含、重合导致顺序歧义或重复ID时直接报错；框边界重叠但左右端点同向递增时保留两框按左右顺序排列。`--layout auto`（省略参数时的原有行为）用于其他图片，支持可判定的单栏和有明确栏间距的双栏，双栏按页眉、左栏、右栏、页脚排序。只使用 `dt_boxes`，不调用模型猜顺序，不改写原文。多栏、正文跨栏或无法确定栏间距会明确报错；复杂布局没有“通用排序已验证”的保证。
- `timing.requestMs` 包括上传、网络、服务排队、识别和下载；`reorderMs` 为本地校验与排序；不把请求总时间宣称为纯推理耗时。逐人记录截图命令、OCR 命令、Agent 阅读分析及墙钟总时长，并单列回执中的 `requestMs`、`reorderMs`。Agent 从首次读取完整重排文字及置信度材料开始，到结果保存结束；包含必要的原图核验及工具间隔，不冒称纯模型推理时间。总时长包含检查和调用间隔，不用阶段之和替代。

此步骤完成文字提取与排序，不替代候选人资格判断，也不扩大联系、收件或 HR 导入授权。
