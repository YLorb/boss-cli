# 推荐 SOP

在线简历截图成功后，立即按[异步 OCR 规范](resume-ocr.md)由 Agent 后台执行公开 `ocr` 命令；等本人的结果完成后优先读文字评估，保留原图核验。不得以异步为由跳过逐人处理、提前评分或触达。 截图到底后不向上恢复；截图后保持简历打开在底部，等待本人的 OCR 和 Agent 结果，再决定沟通或退出；等待期间不操作下一人。


读取[共用规则](common-rules.md)和[账本](ledger-and-recovery.md)。确认 JD、评估标准、可选否决项、N、触达门槛和动作范围。

仅查看、不联系时不要求触达门槛或话术，不启动正式 collect 写会话。查看或截图错误按[错误分级与继续条件](non-contact-continuation.md)；下文异常停止指停止受影响对象，是否继续下一人由该规则决定，身份检查仍不可省略。

1. 保存输入和本轮进度。正式业务启动目标岗位 collect，检查恢复状态及 show；仅查看验收使用独立运行记录。
2. `node .\dist\cli\index.js recommend '岗位名称 _ 城市' --ensure-job --json`。以岗位名称＋城市作为唯一匹配键，忽略薪资后缀；下拉只搜索岗位名称，再核对城市。共用选岗函数默认比较当前岗位，同键直接返回，不重复点击岗位。省略ensure-job支持关键词，但多项匹配仍暂停；简称匹配到当前岗位时仅收起下拉。此规则同样覆盖greet --job。
3. 保存列表快照中的姓名及 geekId，逐人检查已有账本、本轮记录和人工接管名单。名单不能从其他使用者的历史数据继承。读取器每张实际卡片只输出一次，work/education 为工作和院校数组，experience 为兼容合并文本。
   如果当前推荐卡片输出含可核验院校信息，可先按用户硬性条件预筛，记录原文及排除原因，避免打开明确不符合的简历；字段不可读或证据不足不猜测，按未知项规则处理。预筛与实际打开人数分别计数，不能把卡片摘要当作完整评估。
4. 打开前检查 N 与身份唯一性，再执行 `preview '姓名' --candidate-id '快照geekId' --json`，核验返回 candidateId 与 identityVerified=true，计数、核对截图回执，再按上述 OCR 流程及用户标准评估。姓名必须精确匹配，ID须来自当前同一卡片；无ID时重名暂停，提供ID仍不唯一或卡片/简历ID不符则停止，不自动选择第一人。经历字段仅辅助快速预筛，缺失时允许查看简历，不因空字段判淘汰。
   推荐页截图的固定/吸顶元素检测仅输出提示，不因此中止；仍须通过 CLI 的滚动到底与重叠一致性等完整性校验；Agent 优先读取 OCR 文字，仅低置信度或决定性字段有疑点时核对原图，记录证据和疑点。提示不代表截图失败，也不证明正文无遮挡；实际校验失败按第7步处理，不使用不完整截图评分。
5. 不合适只写本轮忽略；证据不足记待确认。仅查看模式不执行联系。合适且获准联系时先保存触达意图，再按下文推荐联系步骤操作。点击打招呼不代表聊天已打开，不得直接跳转沟通页补发消息3。
6. 返回列表后核对岗位仍正确；本轮不重新执行 recommend 刷新候选人。列表变化时保存新身份依据，不能用旧序号猜测。
7. 达到 N／额度限制／列表耗尽／用户停止，保存并报告后结束本轮；操作异常默认停止，已启用不联系继续模式时按错误分级处理。不要反复调用 preview 检查同一人。

推荐联系：返回列表后先执行 `greet '姓名' --candidate-id '快照geekId' --check --json`，为true且已获联系授权才去掉--check执行一次。姓名/ID/卡片组件须一致；简历覆盖列表时不点击底层卡片。可选--job换岗可能改变列表，换岗前后都核验同一ID，不刷新寻找。成功回执返回candidateId、identityVerified及status=clicked；点击成功不是沟通成功，既有发送证据优先，不能重复问候。完整自动编排未实现，命令需要 Agent 串行执行并核验。

### 打招呼后的边界

用户明确要求“已触达不补消息3”时，先按[共用规则中的不补发例外](common-rules.md#联系与消息仅在获准时读取执行)排除历史补发与中断恢复补发；下述连续流程仅适用于本轮新触达且未中断的对象。不得把历史“待发消息3”当作新的发送授权。

推荐页 `greet` 不负责跳转沟通页或打开聊天，`--continue-chat` 仍仅支持搜索页。推荐使用以下独立步骤，全部在当前推荐页串行执行：

1. 保存打招呼回执和原卡片 ID，不重复 greet。确认简历已退出、原推荐岗位未变。只有按钮已变为“继续聊”或“继续沟通”时，使用正式打开命令；仍是打招呼、未知文案或按钮缺失直接停止。
2. 执行 `chat '卡片显示姓名' --recommend --open --candidate-id '已联系ID' --recommend-job '岗位名称 _ 发布城市' --job '聊天岗位原文' --json`。recommend-job 用于核对推荐页岗位（忽略薪资），job 用于严格核对小窗中的岗位原文；两者不能互相猜补。命令复用会话锁和页面守护，核验卡片 DOM/组件 ID 和姓名，确认按钮可见、唯一且无遮挡，只点击一次继续聊；不选择岗位、不打招呼、不导航。已有同人同岗位小窗则只核验复用，不再点击。
3. 首次点击后在 5 秒内核验主文档中的唯一小窗，包括 candidateId、岗位、conversationId、编辑器关联及 friendId。缺失字段在该窗口内等待就绪；已填充字段发生身份／岗位冲突立即停止，不把冲突当加载中。聊天姓名可能解除脱敏，只有 ID 与关联全部匹配才返回实际姓名 target.name；后续命令使用返回的 target。若实际页面结构与支持的布局不符、出现其他人／其他岗位、导航或超时，保存回执并停止，不跳转沟通页补救、不重试。
4. 使用 `chat '实际姓名' --embedded --check --candidate-id 'ID' --job '聊天岗位原文' --json`，并检查已有消息及运行回执。待发消息3尚未发送且授权有效时，先保存发送意图，执行 `send --embedded --name '实际姓名' --candidate-id 'ID' --job '聊天岗位原文' --text '已确认消息3完整正文' --check --json`；预检通过后去掉 --check 发送一次。check=false 不能当成发送成功；若完整正文已存在，记录证据并跳过发送。
5. `send --embedded` 复用锁和守护，保护草稿、核对完整正文、固定会话与页面，只有同一收件人的新己方消息 ID、正文及可见证据全部匹配才返回 message-visible；已加载同人己方完整正文存在则返回 already-visible 且 sent=false。它不搜索全部历史；仍须核对本地发送回执。结果不明不补发。
   `EmbeddedSendUnconfirmedError` 表示发送键已尝试、回执未确认，不代表没有发出。保存完整 error.details 和公开 `chat --inspect-embedded --json` 的只读输出，按“发送结果待核验”停止；不得裁成消息前几十字后宣称全文送达，不得重跑 send/greet。诊断中的 false 项用于定位原因，不授权放宽身份或成功判定。
6. 核验结果后执行 `chat '实际姓名' --embedded --close --candidate-id 'ID' --job '聊天岗位原文' --json` 关闭对应小窗，再用 status 核对仍在原推荐页及岗位。草稿、遮挡、身份变化或超时均停止。conversationId 不直接当作正式账本 dataId；未核实映射时保留待关联回执，不捏造入账成功。

只确认点击时保留“联系结果待核验”；联系确认而消息3未完成时保留“已联系待发消息3”。上述流程不会因某步失败而重放前面的触达或发送，也不会自动操作下一人。

验证范围：2026-10-30 用户报告三例首次打开误报及发送确认超时。首次加载竞态已离线复现并修复；发送后历史日志仅保留正文片段，尚不能定位具体失败字段。新增逐项诊断，不宣称发送超时根因已修复。以上修改通过隔离 DOM 和模拟会话测试，尚未线上验收。CLI 仅支持卡片上的既有继续聊按钮和主文档内嵌小窗，不直接调用页面组件方法或内部聊天事件。
