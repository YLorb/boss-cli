# 推荐 SOP

读取[共用规则](common-rules.md)和[账本](ledger-and-recovery.md)。确认 JD、评估标准、可选否决项、N、触达门槛和动作范围。

1. 保存输入和本轮进度。正式业务启动目标岗位 collect，检查恢复状态及 show；仅查看验收使用独立运行记录。
2. `node .\dist\cli\index.js recommend '岗位名称 _ 城市' --ensure-job --json`。以岗位名称＋城市作为唯一匹配键，忽略薪资后缀；下拉只搜索岗位名称，再核对城市。共用选岗函数默认比较当前岗位，同键直接返回，不重复点击岗位。省略ensure-job支持关键词，但多项匹配仍暂停；简称匹配到当前岗位时仅收起下拉。此规则同样覆盖greet --job。
3. 保存列表快照中的姓名及 geekId，逐人检查已有账本、本轮记录和人工接管名单。名单不能从其他使用者的历史数据继承。读取器每张实际卡片只输出一次，work/education 为工作和院校数组，experience 为兼容合并文本。
   如果当前推荐卡片输出含可核验院校信息，可先按用户硬性条件预筛，记录原文及排除原因，避免打开明确不符合的简历；字段不可读或证据不足不猜测，按未知项规则处理。预筛与实际打开人数分别计数，不能把卡片摘要当作完整评估。
4. 打开前检查 N 与身份唯一性，再执行 `preview '姓名' --candidate-id '快照geekId' --json`，核验返回 candidateId 与 identityVerified=true，计数、核对截图和按用户标准评估。姓名必须精确匹配，ID须来自当前同一卡片；无ID时重名暂停，提供ID仍不唯一或卡片/简历ID不符则停止，不自动选择第一人。经历字段仅辅助快速预筛，缺失时允许查看简历，不因空字段判淘汰。
   推荐页截图的固定/吸顶元素检测仅输出提示，不因此中止；仍须通过滚动到底与重叠一致性等完整性校验，并核对成图正文是否可读。提示不代表截图失败，也不证明正文无遮挡；实际校验失败仍按第7步停止。
5. 不合适只写本轮忽略；证据不足记待确认。仅查看模式不执行联系。合适且获准联系时按共用规则建立沟通、入账和发送消息3。
6. 返回列表后核对岗位仍正确；本轮不重新执行 recommend 刷新候选人。列表变化时保存新身份依据，不能用旧序号猜测。
7. 达到 N／额度限制／列表耗尽／用户停止／操作异常，保存并报告。不要反复调用 preview 检查同一人。

推荐联系：返回列表后先执行 `greet '姓名' --candidate-id '快照geekId' --check --json`，为true且已获联系授权才去掉--check执行一次。姓名/ID/卡片组件须一致；简历覆盖列表时不点击底层卡片。可选--job换岗可能改变列表，换岗前后都核验同一ID，不刷新寻找。成功回执返回candidateId、identityVerified及status=clicked；点击成功不是沟通成功，既有发送证据优先，不能重复问候。完整自动编排未实现，命令需要 Agent 串行执行并核验。
