# 沟通页候选人定位流程

依据用户 2026-10-26 的真实演示：在沟通页使用姓名搜索定位已有候选人。此处搜索不是 `/web/chat/search` 的人才搜索，也不建立新联系。

## 操作步骤

公开命令：`node .\dist\cli\index.js chat-search "完整昵称" --json`。可加 `--data-id "预期会话ID"`、`--job "预期完整岗位"` 作定位后的比较标准；这些参数不能用于自动挑选重名。命令不支持 `--check`，不会发送消息。已有搜索输入或结果时直接报错，请用户先清空，不覆盖、不复用旧搜索。

现有 `chat "完整昵称"`、`chat "完整昵称" --data-id "ID"`、`chat --index N` 和指定候选人的 send／probe-resume／accept-resume／download-resume 均已接入此唯一路径，原姓名与联合键滚动查找代码已删除。姓名始终精确匹配，`--strict` 保留兼容；序号入口仅从当前列表读取姓名、ID和岗位，再搜索核验，不滚动点击原行。

1. 确认当前位于 `/web/chat/index`，记录待定位的候选人昵称及已知岗位、会话 ID。仅定位不包含发送、收件、下载或评估授权。
2. 打开沟通页岗位下拉框，选择页面实际文案“全部职位”，核验已选中。岗位下拉的“全部职位”与顶部会话分类“全部”是不同控件。
3. 点击岗位框右侧搜索图标（演示中为 `.chat-search-btn`）。
4. 在占位文案为“搜索姓名/群聊”的输入框中输入候选人完整昵称（演示中为 `.chat-top-search .search-input`），等待当前输入对应的匹配列表出现。
5. 在点击前读取并保存完整匹配列表，核对昵称及结果附带的公司文案。**出现重名或多个可能匹配项时立即暂停，不点击任何结果，等待用户手动确认或进一步指令。** 不自行按公司、岗位、排序或历史 ID 挑选，不试点多个结果。
6. 只有明确唯一匹配时，点击该匹配项完成确认。真实演示中输入“黄子佳”后点击“黄子佳_湖南森纳信息科技有限公司”；没有独立确认按钮或回车步骤，不能凭空增加。
7. 会话打开后，核对实际姓名、data-id 和目标岗位；原先已有可靠会话 ID 时必须一致。全部职位只表示搜索范围，不改变目标 JD 或正式账本岗位。身份不符或无法唯一核验时暂停后续动作。
8. 保存输入、匹配项、选择依据、会话联合键及定位结果。用户手动选择后仍须重新核验第7步；收到进一步指令后仅按其明确范围继续。

## 停止与能力边界

- 无匹配、结果未加载完整或无法确认查询已生效时，保存当前状态并报告，不能点击首项、改词、刷新或改用滚动扫描兜底。
- 本流程用于明确指定对象的已有会话定位。用户已明确要求用全部职位搜索替换现有定位方式；未读收集仍固定本轮起始快照，只搜索其中的对象，不将全岗位匹配结果变成新增处理范围。已知ID及岗位须按原对象核验，不使用变化后的旧序号。
- `chat-search` 及现有会话定位入口共用搜索实现；`boss search` 会进入人才搜索页，不能代用。定位必须已在沟通页，不隐式导航；`status --json` 的 `chatSearch` 字段提供只读输入及完整结果快照。错误直接暴露，不自动清空、补点或滚动回退。只读 `--check` 保持原语义，不搜索或定位。
- 返回 `status=needs-confirmation`、`clicked=false` 及完整联系人匹配项（包括“查看更多”下隐藏项）表示暂停；同时存在群聊结果也暂停。不得将暂停当作已定位。唯一联系人精确匹配后点击一次，核验选中会话 data-id 与搜索结果 uniqueId、姓名及实际岗位，成功返回 `status=opened`。
- 对于chat及后续业务定位，重名通过 `CandidateSelectionRequired` 错误中止（消息保留完整匹配信息），不执行发送、同意、下载或读取候选人摘要；collect当前轮次立即停止，不继续下一人，不把暂停写成附件失败或RECHECK。等待用户手动选择或进一步指令，不自动用已有ID绕过暂停，也不自动恢复。用户确认后的动作仍须核验真实会话身份。
- 已完成隔离浏览器测试：唯一匹配、隐藏重名暂停、群聊歧义、已有输入拒绝覆盖、无结果、错误页面及会话ID／岗位不符停止。真实演示已验证唯一结果的手动路径；真实重名场景尚未验收。
