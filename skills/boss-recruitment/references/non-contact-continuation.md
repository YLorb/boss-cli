# 不联系模式的错误处理

## 范围与优先级

仅在用户明确选择“仅查看、不联系，局部错误后继续”时启用，适用于常规搜索／推荐。它细化这两个 SOP 的停止范围，不改变默认联系、未读收集、附件处理的停止规则，也不授权后台自动修复代码。

允许按原 SOP 搜索、读取卡片、查看和截图在线简历、评估及保存独立回执。禁止 greet（包括联系选岗及继续沟通）、send、请求／接受附件、平台“不合适”等候选人处理动作，不写正式 collect 账本、不上传 HR 系统。不需要联系话术或触达门槛。这里“不联系”不表示页面完全不变，也不保证平台不记录浏览行为。

“错误后继续”只指跳过已确认不影响后续操作的失败对象；不重试失败命令，不刷新、不换工具、不换模型、不猜身份，不隐瞒原始错误。用户人工叫停优先于所有继续规则。

## 错误分级

| 类别 | 例子 | 处理 |
| --- | --- | --- |
| 已确认局部错误 | 一份完整截图无法读清；单份评估格式不合格；一张卡片缺少 ID；单份截图完整性检查失败 | 先记“处理失败／待核对”，不评分为不合适；通过下述全部继续条件后处理快照内下一人 |
| 非核心产物错误 | 汇总文件导出失败，但逐人回执已成功保存 | 保留已有结果，记录导出错误；继续条件成立时可继续筛选，不重新导出循环重试 |
| 全局阻塞 | 登录失效、验证码、额度限制、浏览器断连、页面／岗位／关键词改变、未知弹层、列表解析整体失败、回执无法保存、模型服务明确报鉴权／余额／限流／服务不可用 | 结束本轮受影响的页面和评估流程，保留已完成结果并报告；不继续采集大量无法评估的材料 |
| 未知错误 | 无法判断影响范围，或缺少当前状态证据 | 默认阻塞；只有原始错误与一次公开只读状态核验足以证明局部、且全部继续条件通过时，才按局部处理。无法证明就结束本轮，禁止凭推测归为无害 |

一张卡片缺 ID 是局部问题，列表整体 ID 缺失或解析异常不是。单份评估格式错误可局部处理，模型连接超时影响范围不明时按未知错误处理。连续两名不同候选人在同一步骤出现同类错误，视为可能的共同故障，结束本轮并报告；不继续用新人探测故障。

这些处理以 Agent 仍能执行为前提。若 WorkBuddy 自身的模型服务中断、额度耗尽或进程退出，Skill 无法保证继续运行或生成结束报告；以 WorkBuddy 运行状态和最后已落盘回执为准，恢复后核对进度，不把未写回的结果视为成功。

## 每次错误后的继续条件

按顺序执行一次，任一失败均结束本轮，不循环恢复：

1. 等待失败 CLI 子进程确实退出。超时但进程仍活动、退出状态不明时，不启动下一条页面命令、不杀其他招聘进程。
2. 将原始错误、命令和退出状态保存到独立回执，并确认保存成功。禁止吞掉错误；日志保存失败时在对话报告，不能声称已经落盘。
3. 通过公开 `status --json`／有明确条件的 `check` 核验当前状态。页面、岗位、关键词仍符合本轮配置；无人工接管迹象、登录／验证／付费等未知阻塞；当前列表和下一人的身份仍可核验。读取失败、身份不一致或无法定位到原列表时结束本轮。
4. 如果仍打开本轮失败对象的已知在线简历，只有状态证据能核对其身份，且本轮已允许“关闭本轮打开的简历”时，才显式执行一次 `back --if-open --json`，再核对原列表、岗位／关键词及无弹层。关闭失败、对象不明、未知弹层或人工接管时不得关闭。此步骤是已知简历的收尾，不是失败动作的备用执行路径；不刷新、不重新查询、不重新打开失败对象。
5. 下一人必须来自本轮快照，按来源＋候选人 ID 核验当前卡片，不使用旧序号；本轮失败对象不再尝试。观察预算及尝试预算仍有剩余，且未触发连续错误停止条件，才继续原 SOP。

仅返回“检查通过”不代表原步骤成功。跳过者保持失败状态；不会因为下一人成功就清除错误。

## 记录、预算与跨轮次

- 使用固定绝对 runDir 保存每轮独立记录；沿用 run.example.json 的 records，并记录每人来源、岗位、可靠 ID（缺失则明确为未知）、阶段、时间、原始错误、命令退出状态、证据路径、当前页面核验结果、能否继续及原因。这些是 Agent 回执字段，不是 CLI collect 新状态。
- 每人处理后立即落盘。报表分别统计已确认打开、评估完成、符合、不符合、待确认和处理失败；失败者不计为不符合，卡片预筛不冒充完整评估。
- 保留原观察上限 N；另用等于 N 的打开尝试上限，每次调用 preview 前记一次尝试，报错也消耗一次，不因未知打开结果而补足人数。分别报告尝试数和确认打开数，绝不声称未知打开“未发生”。
- 下轮读取固定目录历史记录，按岗位＋来源＋可靠 ID 去重。评估完成者不重复打开；局部失败者默认保留待核对，不自动重试，用户明确要求复查后才重新处理；缺失 ID 不用姓名猜测合并。
- 全局阻塞结束本轮，不擅自删除或禁用 WorkBuddy 定时任务。下一次触发先检查前轮是否仍运行、登录与页面条件以及已记录阻塞；阻塞未解除就报告并结束，不重新触发失败的业务动作。人工停止的任务不得由新一轮擅自恢复。
- 记录无法读取、历史损坏或运行状态不明时，不能用空历史继续。不得直接更改正式账本、解除 RECHECK 或清除锁。

## WorkBuddy 配合方式

先在人工监督下完成安装、登录、岗位／关键词配置及一次不联系运行，再由用户创建本地定时任务，选择招聘 Skill、固定模型和固定工作目录。JD、筛选条件、入口、N、排除名单及 runDir 保存到固定配置文件，定时提示词引用其绝对路径，不依赖旧聊天记忆。

同一 BOSS 浏览器只能有一个操作者。首次配置时核验 WorkBuddy 是否能避免任务重叠；不能确认时不承诺无人值守并发安全，先采用人工触发。每轮仍检查其他任务和人工使用情况，发现占用或无法确认独占则结束本轮，不抢占页面、不关闭别人的窗口。仅错开时间、保存一个“运行中”文字标记都不是原子互斥保障。本 Skill 不实现调度器、跨进程锁或 WorkBuddy 平台设置。

让 HR 使用浏览器的时间与自动任务分开；不联系候选人并不意味着可与 HR 同时操作同一个页面而互不影响。

以下提示词中的方括号需在首次配置时填写；缺失必需配置时报告缺项并结束，不在无人值守运行中猜测：

> 使用 boss-recruitment Skill，读取固定配置文件 [配置文件绝对路径]，按其中 JD、条件、搜索或推荐入口及人数上限执行。仅查看和评估，不打招呼、不发消息、不请求或接受附件、不写正式候选人账本、不上传。启用“不联系模式的错误分级”：单人错误先保存并报告，确认原列表和下一人身份可靠后跳过继续，不重试；允许关闭本轮打开且身份已核验的在线简历。登录失效、验证码、页面状态不明、共用服务故障或记录保存失败时结束本轮并报告。使用固定记录目录 [runDir绝对路径]，读取历史去重，失败者保留待核对。同一浏览器已有任务或人工操作时不启动、不抢占。完成后展示候选人结果、处理失败清单、已完成进度及需要我处理的事项。始终遵守 Skill 工具边界，只使用已核验 boss-cli 公开入口。

## 面向用户的报告

局部错误用一句话说明，然后满足继续条件即继续，不要求逐个确认：“这份简历暂时没能完成评估，已记录问题；列表状态已核验，继续查看下一位。”

本轮结束报告：尝试／已确认打开／评估完成数量、候选人结果及证据、失败清单（人、阶段、原因、是否跳过）、保存位置、整体完成／部分完成／阻塞、需要人工处理的事项。禁止把部分完成报成全成功。

全局错误示例：“本轮已完成 12 人，因登录失效结束；结果已保存。请重新登录。定时配置未被本 Skill 修改，下次触发仍会先检查条件。”只在实际已保存时使用该措辞。

本规则是 Agent 编排约定，不表示 CLI 已实现自动跳过、定时调度或恢复，也不代表 WorkBuddy 已安装此版本或已通过真实页面验收。
