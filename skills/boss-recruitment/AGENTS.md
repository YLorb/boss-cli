# 招聘评估的上下文与 OCR 汇总约束

本轮初始化时先在上下文中读取指定岗位的完整 JD、评估规则及操作边界，并将其作为本轮固定依据。后续评估候选人时，不重复粘贴或复述这些内容，不自行改写、概括、删除或调整其含义。

需要生成上下文摘要时，必须完整保留当前有效的 JD、评估规则、操作边界及用户明确修改；候选人历史过程可缩减为结果和证据位置，不得用旧结论替代当前规则。

优先将 CLI 返回的完整长图交给一次公开 OCR 命令，不由 Agent 独立切片或重复提交覆盖同一材料的截图。CLI 在请求前同时检查字节数与像素高度：仅当不超过 3 MiB 且高度不超过 1984 像素时上传原图；否则段数取字节需求 ceil(原图字节数 / 3145728) 与高度需求的较大值，高度超过 1984 时高度需求为 ceil(原图高度 / (1984 - 256))，否则为1。沿高度均分，相邻段重叠 256 像素（极矮图片按高度缩小重叠），保持原像素。裁剪编码后预检每段实际字节数及包含重叠区的高度，不得超过 3 MiB / 1984 像素；超限直接报错，全部停止上传，不自动追加裁剪。所有段全部成功后还原原图坐标，在每个重叠区文字框之间选择分界线消重；任一边界无安全分界线则报错，不生成部分文字。提交前核对本人的截图与任务记录：已有任务则等待该任务，已有成功且输入一致的结果则复用；仅对尚未覆盖的必需材料发起新的 OCR。识别失败时按现有失败规则停止，不重试、不追加切片。

同一候选人的所有必需 OCR 结果成功返回并核验归属后，统一整理文字及来源，再进行一次完整评估。不要逐张截图反复评分，不把其他候选人的完整材料持续累积到当前评估输入中。

## 简历解析耗时目标

从本人的截图或附件落盘、可供解析起，到文字提取和 Agent 结构化结果完成，争取30秒内；不包含之前的页面定位、滚动截图或附件下载。分别记录文字提取耗时、Agent处理耗时及总耗时，不能用其中一段冒充全程。

## 简历解析提速五项执行规则

1. **文字优先**：优先读取 OCR 重排后的完整文字，仅在低置信度或决定性字段有疑点时核对原图。保留原图及来源，不把 OCR 漏字当作事实缺失。
2. **一次判断**：完整 JD 和规则每轮加载一次，保持原文；只携带当前候选人的材料和必要去重状态。等本人的必需材料齐全并核验归属后，一次完成全部规则的评估，不逐张评分、反复生成评价。上下文缺失时仍须按下文重新读取。
3. **减少重复材料**：按候选人归属和输入哈希复用成功 OCR；已有任务则等待，不重复识别完整长图及其覆盖的切片，不为重复阅读而再次打开同一简历。业务动作必需的打开和身份核验仍须执行。
4. **缩短输出**：只保留用户要求的结论、各项规则对应证据、缺失或冲突信息及下一步；不复述整份简历或 JD，不因缩短输出省略用户要求的评估项。固定保存、校验和计时逻辑预置为脚本；Agent 只生成字段或证据行号，不逐人重写保存程序。符合明确字段格式的文字收集可按[紧凑交接与计时](references/resume-analysis.md)执行，证据由脚本从本人原文展开。
5. **区分收集与筛选**：用户要求仅收集时，完成材料保存、身份核验、文字提取和回执，不额外做匹配评分或淘汰判断；要求筛选时才执行已确认的 JD 和评估规则。

OCR等待期间可整理本人的回执和规则，禁止提前触达或处理下一人。

30秒是目标，不是宿主强制限时或准确性保证；超过时记录实际耗时及原因，未核验的字段标待核对，不猜补、不自动换模型或服务，不把超时当作候选人不合格。

以上约束适用于 Agent 能控制的上下文整理行为，不代表已关闭宿主自动压缩或滑动窗口。若规则内容已缺失或无法确认完整性，应重新读取指定规则文件后再评估，不凭摘要、记忆或猜测补全。
