# 浏览器启动问题静态审查

日期：2026-11-09。检查当前源码和已安装的 Puppeteer 实现；未执行真实 BOSS 操作。本记录列出待修复项，不表示问题已经解决。

## Chrome 常驻

当前通过 spawn(detached:true)、unref 启动，login 返回前断开 CDP。该设计无法保证宿主不回收子进程。沙箱相关环境变量、浏览器短暂存活和一次后台 shell 成功，不足以证明具体回收机制或长期存活。

应使用宿主正式支持的长任务方式承载公开 CLI，并提供存活、断连和退出回执。宿主不支持跨任务存活时明确报告限制，不承诺后台无限循环一定有效。

## 视口补丁的确定缺口

待提交的 boss_session_page.ts 补丁在任意维度不足时同时覆盖宽高。例如1920×1080遇到1280×1200目标，会缩窄为1280×1200，可能引入横向越界。viewport为null时也会无条件覆盖真实窗口。

需要先读取实际 CSS 视口，宽高分别决定是否扩大，保留设备参数，设置后核验实际 innerWidth/innerHeight，并在截图前核验目标区域确实位于视口内。

本机 Puppeteer 的 Page._create 只在 defaultViewport 为真值时调用 setViewport；显式 null 不会自动套用800×600。发现800×600仍需核实实际调用版本和视口设置入口，不能直接归因于复用连接。Page.setViewport 在移动端或触摸模拟状态改变时会 reload，一次无导航观察不构成普遍保证。

## CDP 探测错误分类

cdp_browser.ts 的端口探测将HTTP错误、响应损坏、超时和连接拒绝都变为undefined，随后进入新Chrome启动路径。已有浏览器只是响应慢时可能触发重复启动及用户目录锁冲突。

需要区分明确未监听和探测失败；后者包含端口、阶段和原始原因并停止，不静默转为启动新实例。

## 推荐岗位切换

当前源码只将 changed===page.mainFrame() 认定为顶层导航。点击前推荐iframe失效会中止；点击后允许原iframe导航、分离及该次点击响应上下文销毁，再从主页面只读确认新iframe岗位，不重复点击。

新增10个离线场景覆盖上述事件顺序、确认期间顶层导航、错误岗位、超时和非上下文类点击错误。真正顶层导航仍须中止；等待5秒后成功不能单独证明原始失败的根因，也不应据此内置自动重放。

## DPI 与启动就绪

注册表DPI不能单独证明当前窗口缩放和页面缩放。不需要为此修改系统显示设置；应使用实际CSS视口、DPR及PNG尺寸核验。
