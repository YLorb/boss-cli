## 推荐页避免重复选岗与安全返回（2026-10-15）

循环中核验岗位使用 `node .\dist\cli\index.js recommend "岗位完整名称" --check-job --json`。相同岗位不重复点击；不要以模糊简称代替完整名称。

需退出当前在线简历时执行 `node .\dist\cli\index.js back --check-in_online_resume --json`：弹层关闭，独立简历页面经历史目标核验后回退，已经在列表则不操作。截图成功会自行关闭简历，通常无需再执行 back。

异常不再自动跳回沟通首页或重跑整个业务动作；读取原始错误并核对页面状态，不重复发送。截图和 greet 均保持视口尺寸；截图以可见视口采集后本地裁剪拼接。详见 [URL 与命令规范](boss-url-map.md#推荐页状态保持与返回2026-10-15)。

## 搜索候选人的立即沟通（2026-10-20）

本地新版已补搜索 `greet`。先核对当前搜索条件及完整显示姓名，执行 `node .\dist\cli\index.js greet '姓名' --check --json`。`ready` 仅表示候选人和按钮已核对；取得本步联系授权后，再执行不带 `--check` 的同一命令。在线简历已打开时，以卡片与简历操作组件的候选人 ID 核对身份，在主页面对应简历的右侧操作区定位按钮；不关闭简历去点击底层卡片。不支持搜索 `--job`。

返回 `already-contacted` 不重复联系；`contact-confirmed` 只说明观察到按钮变为“继续沟通”。消息3、会话关联和入账仍要分别核验。发生“点击后未确认”时暂停，不补点，不处理付费或二次确认弹层。已完成离线回归和真实 n** 的只读预检，返回 identityVerified=true、ready、clicked=false；随后按用户授权点击一次，出现联系岗位选择弹层；未选岗或二次确认。

## 联系弹层选岗规则

用户已明确指定本轮招聘目标岗位时，直接选择弹层中的对应岗位；未指定时先向用户确认，不采用默认选中项，也不将搜索条件“不限职位”当作联系岗位。简称须先核对唯一完整名称，歧义时询问用户。

使用 `boss greet "完整显示姓名" --select-job "联系岗位完整名称" --json`；可加 `--check` 只读核对。CLI 核对候选人 ID、精确匹配岗位并验证选中状态；该步骤只选岗，不点击弹层“立即沟通”。后续确认遵循用户当前授权范围。

确认联系使用 `boss greet "完整显示姓名" --select-job "已选岗位完整名称" --confirm-contact --json`，可先加 `--check` 只读核对。要求候选人身份与已选岗位一致，不自动改选，只点击弹层确认一次。弹层关闭且同一候选人的按钮变为“继续沟通”后返回 `contact-confirmed`、`contactConfirmed=true`；失败不得重试。仅在用户已授权联系时执行，消息3及入账仍为独立步骤。

2026-10-20 实测：n** / 大模型推理加速专家已完成弹层确认，CLI 返回 `contactConfirmed=true`。本次未单独发送消息3或写入账本。

已联系后打开会话：`boss greet "姓名" --continue-chat --candidate-id "成功回执中的候选人ID" --json`。要求当前简历仍打开，核对该 ID 的两处组件数据；不依赖联系后可能移除候选人的搜索列表。可加 `--check` 只读核对。`continue-clicked` 只确认点击，不证明已打开独立沟通页。
