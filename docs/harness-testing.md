# 招聘资料归档的自动化测试

`BOSS-Harness-20261106.zip` 是 WorkBuddy 招聘运行归档，Harness 指招聘岗位。它不是测试框架，也不是可执行的测试规范。

归档包含1104个文件：评估／运行记录757个、JD与口径6个、OCR文件238个、PDF13份、截图82张、账本7份。82个OCR目录中78份有正文和文字框，4份明确注明未做OCR。72份raw.json是split-manifest，仅保留原分片路径、尺寸和哈希，包中没有对应分片API响应；6份保存了完整单图API响应。

## 一条命令运行

需要当前仓库的Node.js、已安装的npm依赖，以及Python3标准库。Python路径通过参数明确指定；默认使用PATH上的python，失败直接报错，不自动换解释器。无需解压整个资料包或执行其中任何脚本。

Windows 使用 Git Bash 提供的 sh，Linux／macOS 使用系统 sh。从仓库目录运行：

```sh
sh scripts/test-harness.sh --archive 'E:/资料/BOSS-Harness-20261106.zip' --python 'C:/Python312/python.exe'
```

`.sh` 入口通过 `"$@"` 保留参数边界，直接执行同目录的 Node 测试程序。包含空格的路径须加引号；Windows 路径建议使用上例的正斜杠形式。可从 PowerShell 调用已在PATH中的sh，无需PowerShell脚本或npm参数转发。Node.js与Python路径均需在当前环境中有效；不会自动安装或切换解释器。

需要直接调用Node时使用 `node scripts/test-harness.mjs --archive '<ZIP绝对路径>' --python '<Python绝对路径>'`。

可指定 `--output output/harness/<全新目录>`；已有运行标记的目录拒绝覆盖。默认使用时间戳目录。

所有产物必须位于仓库已忽略的output目录。dataset.json、账本副本和详细失败日志含私人信息，不提交到Git。公开控制台只输出阶段状态、数量和报告路径。脚本不连接真实BOSS浏览器、调用外部OCR、发送消息或修改原ZIP及本机业务账本。守卫安装测试会启动独立headless Chrome，仅访问data:测试文档；需安装Chrome，非默认位置时通过CHROME_PATH指定可执行文件。

## 覆盖范围

正式任务配置、运行绑定、阶段与逐人业务门可单独运行 `sh scripts/test-managed.sh`；加 `--browser-fixtures` 可运行独立合成页面测试。跨宿主与近义表达测试使用 `sh scripts/test-agent-portability.sh prepare output/<新目录>`，后续参考回放与真实宿主执行分别记录。详细命令、实际结果和宿主阻塞见[跨宿主本地验收](agent-portability-testing.md)。脚本存在不代表宿主矩阵已经通过。

| 阶段 | 实际验证 | 边界 |
| --- | --- | --- |
| build | 当前源码TypeScript构建 | 不使用旧dist冒充当前实现 |
| archive | ZIP路径安全、重复项、PNG尺寸、PDF头、OCR材料完整性 | PDF仅检查文件头，不评测正文提取 |
| unit | 账本状态与持久化、命令超时、简历拼接时序、解析交接、选岗路由 | 复用显式列出的合成数据测试，不自动发现线上脚本 |
| flow-lock | 当前流程状态、决策门、日志、防重放、暂停与接续判断 | 运行test-flow-lock.mjs，不能以通过代替完整业务验收 |
| workflow-simulation | 十人固定决策参考预检，局部错误、未决发送、跨进程接续和全局暂停 | 不调用模型；实际Agent任务另行验收，见[流程模拟说明](local-workflow-simulation.md) |

运行报告为summary.json；每阶段有独立日志；replay-report.json逐样本标记passed/failed/skipped。原始数据不完整不会编造通过：4份未OCR样本和72份缺少分片原响应的API回放明确skip。单样本回放失败后可继续检查其他独立样本，最终退出码仍为1；构建或归档读取失败则停止依赖阶段。每阶段180秒超时报错，不自动重试。

同名脱敏截图不能按姓名、文件顺序或最新时间猜测。分片记录必须从其原截图路径取出姓名与时间戳，唯一关联包内截图；完整单图响应只能关联唯一同名截图。无法关联直接失败。

## iframe异常与守卫边界

- iframe缺失、隐藏不选取目标；多个可见面板或iframe不取第一个；contentFrame为空、detached、宿主不一致、定位上下文销毁均拒绝。定位只查已核验宿主，不扫描其他frame找替代目标；获得的句柄在异常后释放。
- 搜索预览既有恢复路径的测试覆盖：身份不一致、城市／岗位／关键词等筛选变化、主框架导航后禁止恢复点击；既有获准重开路径至多一次，第二次失败不发生第三次尝试。测试不新增生产恢复逻辑。
- 即使调用方关闭shell／菜单预检查，也必须获取会话锁并等待守卫安装成功；安装失败或尚未完成时业务回调次数为零。锁获取失败时不连接浏览器。业务上下文销毁时不重连、不重跑。
- 公开switch-job路由拒绝伪造的--skip-guards、--no-guard、--unguarded、--guard=false和--cdp-url参数，拒绝发生在共享会话及页面读取之前。这些参数拒绝断言目前仅覆盖该路由。
- 独立Chrome验证同一文档多客户端重复安装保持幂等，新文档独立安装；安装失败留下未完成状态时，再次安装仍拒绝，不能当作已就绪。

这些测试验证公开入口和公共会话代码的行为，不提供对外部进程直接访问CDP或导入内部模块的技术封锁。陌生域名iframe的完整URL校验、运行中守卫被篡改等场景尚未纳入本组断言，不据此宣称已覆盖。

## 尚不能直接建立的测试

- **筛选质量金标**：历史评估存在口径解释、后续修订和待用户确认的例外。需要先冻结JD与规则版本，再由人工审核学校／经历证据及期望结论。旧Agent结论只能作为待审标签，不能直接成为正确答案。
- **完整分片HTTP响应回放**：需要补齐72份记录引用的part-*.raw.json和相应分片尺寸、偏移与输入哈希，才能检验从每段API响应到最终全文的整条链路。现有已合并boxes只能测排序与来源一致性。
- **外部接口联调与OCR耗时**：需要单独明确目标环境、数据使用范围和期望输出，优先使用虚构简历。当前脚本不将真实简历上传到任何服务，也不能以离线回放速度替代OCR或Agent推理速度。
- **真实页面端到端回归**：资料包缺少页面DOM／网络响应夹具，截图本身不能回放点击、定位与风控状态。应先补隔离页面夹具；真实BOSS验收仍只通过公开CLI按授权逐步执行。

新增问题用例时保留输入哈希、来源、失败阶段、固定规则版本和人工审核后的期望值。不要批量把历史失败改成期望成功，也不要通过放宽断言消除回归。
