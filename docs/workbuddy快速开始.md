# WorkBuddy 使用 boss-cli 简明指南

适用版本：CLI **0.6.16-dev.0** + Skill **1.0.25**（本地开发版，未发布）。

你负责提供岗位、筛选标准和联系权限；WorkBuddy 按 Skill 的操作流程调用 CLI，完成查看、文字提取、初筛和获准的沟通。**无需逐条输入命令**，但扫码登录、部分页面设置和异常确认仍需要你参与。

## 一 风控提示

**CLI 的守护功能不能保证账号不被限制、封禁或影响曝光，也不能提供“每天操作多少次一定安全”的承诺。** 人数上限是本轮任务边界，不是平台认可的安全额度。使用畅聊卡也不取消操作边界。

- **真实 BOSS 操作只走公开 CLI。** 不让 WorkBuddy 另写浏览器控制脚本、直接调用 BOSS 接口，或用其他浏览器／桌面工具补点按钮。CLI 缺能力或报错时，停止受影响步骤并保留记录。
- **逐人完成，不并行操作页面。** 核验身份 → 阅读完整材料 → 评估 → 按授权沟通 → 保存结果，再看下一人。不反复刷新、重复查询、重复打招呼或催发消息。
- **结果不明先停。** 超时不等于没发出去；不能直接补发。验证码、额度限制、未知付费提示、身份不符或页面结构异常都应停止并报告。扫码和验证由用户完成。
- **每轮先检查版本。** 检查实际加载的 Skill 与 CLI 是否配套。不匹配时展示差异，用户明确确认后才能继续；不能自动确认或把确认永久写进配置。
- **明确数据去向。** 截图、账本和回执保存在本机；OCR 会上传简历 PNG 到配置的识别服务。当前默认地址为 `http://ylorb.top:9002/ocr`，使用 HTTP，不能视为加密传输或纯本地处理。首次使用前确认该服务是否适合承载这些材料；不接受时先暂停 OCR 及依赖它的评估，由维护者配置认可的服务。不要分享 Cookie、浏览器数据目录或含真实候选人资料的运行文件。

初筛结论供人工审核。材料未写明的经历记为“待确认”，不要猜补，也不要把 OCR 漏字当成候选人不具备能力。

## 二 环境布置

### 你先准备什么

1. **WorkBuddy**。
2. 已安装的 **Chrome**，以及你自己的 BOSS 招聘账号。

### WorkBuddy 可以自动配置什么

| 项目 | 处理方式 |
| --- | --- |
| Node.js 与 npm | 先检查。本包按 Node 24 验证；缺失时说明版本、来源、安装位置及 PATH 改动，取得你的明确同意后下载安装。 |
| Chrome | 检查已有安装；缺少时由你安装。启动浏览器和进入 BOSS 仍通过 CLI。 |
| CLI | 核验交付来源，解压到新目录，安装依赖并构建；ZIP 安装不要求 Git。 |
| Skill | 使用 WorkBuddy 实际支持的导入方式安装完整目录，核对实际加载路径，不假定固定安装位置。 |
| 保存目录 | 记录 CLI、工作区、简历和本轮回执的绝对路径；已有岗位账本沿用固定目录，不能每轮建空账本绕过去重。 |
| 登录 | CLI 启动或复用浏览器，你完成扫码；WorkBuddy 再通过 CLI 核验登录状态。 |

配置文件只是给 WorkBuddy 的执行说明，CLI 不会自动读取其中所有字段。WorkBuddy 需要把路径、端口等设置实际传给每个命令。不要在运行中自动升级或切换到另一份全局 `boss`。

**复制给 WorkBuddy 的配置提示词：**

> 请配置 boss-cli 和 boss-recruitment Skill，先不开始招聘业务。先读取交付包的 SKILL.md、AGENTS.md 和安装、环境、启动说明。核验 CLI 来源及实际安装路径，导入同包完整 Skill。检查 Node.js/npm；如需安装或修改 PATH，先列出方案并等我确认。Chrome 只检测，不代装。为我记录 CLI、工作区、简历、本轮回执和固定岗位账本的绝对路径，保留已有数据。设置 BOSS_SKILL_DIR 为实际加载的 Skill 目录，完成构建和 version-check；不匹配时提示并等我确认。说明 OCR 服务地址、传输方式和图片上传范围，由我确认使用的服务。环境通过后用 CLI 启动登录，等我扫码再核验。最后报告版本、路径和未完成项，不联系任何候选人。

验收成功应看到：**CLI 入口可用、配套版本匹配、保存路径明确、OCR 服务已确认、登录核验通过**。环境安装成功不代表所有真实页面都已验证。

需要手动核对时，先进入实际 CLI 目录，将下方 Skill 路径替换为真实路径：

```powershell
$env:BOSS_SKILL_DIR = 'C:\Recruitment\workspace\.workbuddy\skills\boss-recruitment'
node .\dist\cli\index.js version-check --json
```

`compatible:true` 才是配套成功。两个版本号采用不同编号，不要求数字相等。详细安装步骤见[安装说明](../skills/boss-recruitment/references/install.md)。

## 三 SOP 与使用示范

SOP 就是固定操作顺序。先选本轮入口，再给 WorkBuddy 明确的目标和权限。

| 入口 | 适合做什么 | 开始前提供 |
| --- | --- | --- |
| 搜索 | 按关键词寻找新人 | JD、关键词、搜索条件、人数上限、目标沟通岗位 |
| 推荐 | 查看平台推荐的候选人 | JD、岗位名称和发布城市、人数上限 |
| 未读收集 | 处理已经沟通、有未读消息的人 | 岗位、本轮范围、附件保存位置、允许发送的话术 |

### 每轮通用顺序

1. **确认输入。** 提供完整 JD、必须满足与加分条件、缺项如何处理、人数上限，以及“仅查看”还是“合适可联系”。没有分数要求时不自行生成评分门槛。
2. **检查环境与历史。** 校验版本、登录、当前岗位和固定账本。存在未核实的发送记录或账本恢复要求时，先处理对应问题。
3. **固定本轮范围。** 保存起始列表，按候选人 ID 去重。姓名相同或被脱敏时，不能凭名字或旧序号认人。
4. **逐人读完整材料。** 截图成功后由 WorkBuddy 调用公开 OCR 命令；已有同图任务先等结果，已有成功结果先核验复用。同一人的必需材料全部齐全后统一评估，不边等 OCR 边联系或打开下一人。
5. **按授权处理。** 仅查看就记录结果；允许联系才核验身份、保存意图并操作一次。消息发送后核对实际会话中的新消息。
6. **保存并结束。** 报告人数、匹配依据、待确认项、联系及消息结果。使用正式账本的流程正常停止并确认落盘。

“看 10 人”指成功打开简历的 **10 位不同候选人**，不合适和信息不足也计数；卡片预筛单独统计。成功打开后截图失败，仍需记录已打开和未完成评估，不能声称已完整评估。

### 搜索流程

先由你设置搜索栏岗位和地点，WorkBuddy 核验后搜索关键词；逐人查看、OCR、评估。列表不足且本轮允许扩池时，才用 `search-more` 在明确滚动及人数上限内追加，按 ID 去重，不刷新重查。

**搜索岗位条件、最终沟通岗位、岗位发布城市是不同信息。** “不限职位”不等于联系时也不选岗；最终岗位必须明确，不能根据候选人期望城市猜测。

允许联系时：身份预检 → 打招呼一次 → 必要时选择已指定的沟通岗位并确认 → 核验联系成功 → 打开正确聊天 → 核对并发送消息3 → 核验发送 → 关闭对应聊天小窗。

畅聊卡出现已知“使用成功”提示时，顺序是：**CLI 关闭使用提示 → 继续沟通 → 小窗聊天 → 核对并发送消息3 → CLI 关闭小窗**。未知购买或付费提示不自动确认。

消息3是岗位／公司介绍，不是求附件。平台默认问候没有包含完整消息3时，仍需按授权发送；完整内容已经发送则不重复。

**示范提示词一：搜索 10 人，只查看**

> 使用 boss-recruitment Skill，先读取 SKILL.md、AGENTS.md 和搜索 SOP，并完成版本校验。目标岗位：[完整岗位名与发布城市]。JD：[粘贴完整 JD]。关键词：[关键词]。必须条件：[条件]；加分项：[条件]；证据缺失记待确认，不自行淘汰或补分。搜索页岗位和地点由我设置，请核验并保留。本轮最多打开 10 位不同候选人，仅查看和评估，不联系、不发消息、不求附件、不写正式候选人账本。允许当前搜索列表不足时扩池，每次最多滚动 3 次、返回池最多 50 人，跨调用按 ID 去重；未到 10 人也不得突破上限或刷新凑数。逐人完成截图、OCR 和一次完整评估。仅使用公开 CLI，失败保存记录并停止。输出已打开数、完整评估数，以及每人的匹配证据、差距和待确认项。

这里的 3 次／50 人是任务示例参数，不是风控安全值，可按本轮范围修改。

**示范提示词二：允许联系并发送消息3**

> 本轮按搜索 SOP 执行，最多查看 [N] 人。目标沟通岗位为 [完整岗位名与发布城市]，JD 和条件见所附文件。只对满足我明确标准的人发起一次沟通；核心经验符合但其他细节未写明时，可先联系核实，并如实记录缺项。我已持有搜索畅聊卡，允许使用现有权益，不购买新权益。联系确认后，核对同一人的聊天和历史消息，尚未发送下面完整消息3时发送一次并核验，之后关闭对应聊天小窗。消息3正文：[粘贴已确认正文]。所有 BOSS 操作只能走公开 CLI；结果不明不补点、不重发，保存状态并报告。

### 推荐流程

核对“岗位名称＋发布城市”，读取起始推荐列表，逐人查看、OCR 和评估。推荐截图后会停留在简历底部，等评估完成再退出；需要从列表联系时，先退出简历，再核验同一候选人。循环中不重复执行推荐入口来刷新候选池。

推荐页点击“打招呼”后留在原页；按钮变为“继续聊／继续沟通”时，用正式 `chat --recommend --open` 打开同人小窗，核验实际姓名、ID和岗位后，通过 `send --embedded` 发送尚未发送的消息3，再关闭小窗。不跳转沟通页、不重复打招呼；失败保留待办并停止。该新增流程已提供离线测试，真实页面尚待验收。

**示范提示词三：推荐寻访**

> 使用 boss-recruitment Skill 的推荐 SOP。目标岗位：[岗位名称 _ 发布城市]；完整 JD：[文件绝对路径]；筛选标准：[条件及未知项处理]。本轮最多查看 5 人，仅查看、不联系。完成版本、岗位和身份核验后固定起始列表，逐人截图、OCR、评估和保存。不得刷新推荐池，不使用旧序号，不绕过 CLI。列表耗尽或报错时报告实际完成数，不为凑人数重查。

### 未读收集流程

在沟通页使用正式 `switch-job` 选岗并核验 → 获取一次起始未读列表 → 按原快照逐人打开 → 查看／提取材料 → 按授权求附件、同意接收或下载 → 核验文件 → 按需发送收件确认 → 保存账本。

本轮新到的未读留下一轮。不把“没有看到附件请求”当作应再次催要的依据。仅收集时不额外评分或淘汰；需要筛选时才按已确认 JD 评估。

**示范提示词四：收集未读简历**

> 使用 boss-recruitment Skill 的未读收集 SOP，处理 [岗位名称 _ 发布城市] 本轮开始时的未读集合。仅收集并提取文字，不做匹配评分或淘汰；固定账本目录：[绝对路径]，附件目录：[绝对路径]。先核验岗位和账本恢复状态。允许在核对历史后发送一次求简历消息：[正文]；有待同意的附件才接收，已有附件则下载并核验文件，成功后按需发送收件确认：[正文]。逐人完成，不刷新未读，不处理本轮新增未读，不上传 HR 系统。错误保存回执并停止；结束确认账本已落盘。

**随时停止可直接说：**“停止所有 BOSS 操作，只保存当前进度，列出已完成动作、结果不明事项和下次恢复位置，不再发消息。”

## 四 已知问题与处理方式

| 问题 | 当前情况与处理 |
| --- | --- |
| 搜索栏不能自动选岗 | 搜索页的岗位筛选仍由用户设置。正式 `switch-job` 只用于沟通页；联系弹层选岗也不能替代搜索栏设置。 |
| 没有一条命令跑完整 SOP | WorkBuddy 负责逐步调用和核验。`collect` 管理岗位账本，不会自动搜索、切换页面岗位或完成未读流程。 |
| 截图不等于全部隐藏内容 | 当前截图针对已展开内容，不自动展开“查看全部”。截图区域、遮挡、底部或重叠校验失败时，不能拿残缺材料作完整评估。 |
| OCR 不可用或识别存疑 | 需要可用的外部服务；公开 OCR 入口仅接受 PNG，不直接解析 PDF／Word。失败不自动重试或换服务；低置信度和决定性字段有疑点时核对原图。 |
| 30 秒解析目标不一定达成 | 该目标从材料落盘到提取文字和结构化结果完成，不含前面的定位、滚动截图或下载；不是保证或统一硬超时。 |
| 联系超时或弹层识别异常 | 可能已经联系成功；先核对同一人的按钮和消息，不能重新打招呼。未知提示保存后暂停。 |
| 小窗有草稿或身份不符 | CLI 会拒绝发送／关闭，不清空草稿强行继续。人工处理后重新核验身份和已有消息。 |
| 账本中断或历史待核对 | 动作回执不会全部自动写入正式账本。正常停止并确认保存；恢复时核对已有结果，不删除标记或新建空账本继续。 |
| 页面变化或同名无法唯一定位 | CLI 的检查可能拒绝操作，需要维护者修复，或用户明确处理；不换工具、不试点其他候选人。 |
| 旧文档与当前能力不同 | 旧迁移说明中“没有扩池／小窗发送”等描述已过时；当前已有 `search-more`、内嵌发送及关闭入口。升级后核对实际 help、配套版本和对应 SOP，不沿用旧脚本许可。 |

**默认错误停止**。只有用户明确选择“仅查看、不联系，局部错误后继续”时，才按专门的[错误分级规范](../skills/boss-recruitment/references/non-contact-continuation.md)判断是否可继续下一人；身份核验和完整性要求不变。

- 中途暂停：可能是等待你的输入或授权
- 错误停止频繁：目前已经极少遇到这样的状态
